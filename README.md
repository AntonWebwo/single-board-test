# Анализ прошивки Single Board Test (SBT) для майнеров Bitmain

Данный репозиторий содержит результаты глубокого реверс-инжиниринга и реконструкции программного обеспечения контрольной платы майнеров Bitmain (архитектура на базе **Xilinx Zynq 7000/7007**). Основной фокус сделан на модуле **Single Board Test (SBT)** — критически важном компоненте, отвечающем за заводское тестирование, калибровку и диагностику хеш-плат с ASIC-чипами серии BM13xx (BM1368, BM1398 и др.).

Код был восстановлен из бинарных файлов путем декомпиляции и переведен в читаемый стандарт **C++11**, сохраняя оригинальную логику, структуры данных и алгоритмы взаимодействия с железом.

> **⚠️ Отказ от ответственности:** Этот материал предназначен исключительно для образовательных и исследовательских целей. Использование данного кода для модификации коммерческого оборудования или незаконной деятельности запрещено.

---

## 🎯 Цель проекта

Понимание низкоуровневой работы контроллера SBT позволяет:
1.  Изучить протоколы взаимодействия между FPGA, ARM-процессором и ASIC-чипами.
2.  Разобраться в алгоритмах частотного свипинга (Sweep), подбора напряжения и температурной компенсации.
3.  Понять механизм защиты данных (EEPROM, PIC-контроллер) и аутентификации оборудования.
4.  Восстановить логику работы с периферией: датчиками температуры, вентиляторами, LCD-дисплеем и сетевыми интерфейсами.

## 📂 Структура модулей и подробное описание

Проект разделен на логические блоки, каждый из которых отвечает за определенную подсистему контрольной платы.

### 1. Ядро системы и Инициализация (`Core & Init`)

*   **`bitmain_main.c` / `init.c`**
    *   **Роль:** Точка входа (`main`) и диспетчер задач.
    *   **Логика:** Обрабатывает аргументы командной строки, инициализирует обработчики сигналов (SIGTERM, SIGINT), запускает потоки логирования и переходит в главный цикл тестирования. Определяет режим работы (PT1, PT2, SWEEP, DropLevel) на основе конфигурации.
*   **`platform.c` / `7007_common.c`**
    *   **Роль:** Абстракция аппаратной платформы.
    *   **Логика:** Проверяет наличие подключенных хеш-плат через регистры FPGA. Инициализирует глобальные структуры данных, такие как `Local_Config_Information`, и определяет возможности системы (количество цепей, тип чипов).
*   **`bitmain_global.c`**
    *   **Роль:** Хранилище глобального состояния.
    *   **Логика:** Содержит массивы результатов тестов (`gHistory_Result`), контекст выполнения (`g_rt`), параметры вентиляторов и температуры. Предоставляет утилиты для расчета статистики (средняя частота, дисперсия nonce).

### 2. Низкоуровневые драйверы (HAL)

Эти модули обеспечивают прямой доступ к ресурсам SoC Xilinx Zynq.

*   **`7007_fpga.c`**
    *   **Роль:** Драйвер программируемой логики (PL).
    *   **Логика:** Использует `mmap` для отображения памяти FPGA. Реализует быстрые операции чтения/записи регистров через таблицы маппинга. Критичен для таймингов UART и управления питанием.
*   **`7007_uart.c`**
    *   **Роль:** Драйвер последовательного порта для связи с ASIC.
    *   **Логика:** Управляет FIFO буферами FPGA для высокоскоростной передачи команд и приема ответов (nonce). Реализует переключение baudrate (медленный для инициализации, быстрый для майнинга) и сброс очередей.
*   **`7007_i2c.c` / `7007_iic.c`**
    *   **Роль:** Драйвер шины I2C.
    *   **Логика:** Обеспечивает связь с внешними устройствами: датчиками температуры (TMP451, NCT218), PMIC (микросхемы питания) и PIC-контроллером. Включает механизмы блокировки (mutex) для потокобезопасности.
*   **`7007_gpio.c`**
    *   **Роль:** Управление линиями ввода-вывода.
    *   **Логика:** Работает через sysfs. Отвечает за сигналы сброса (Reset), включения питания доменов и чтение состояния кнопок пользовательского интерфейса.
*   **`7007_pwm.c`**
    *   **Роль:** Контроллер ШИМ (PWM).
    *   **Логика:** Настраивает скважность сигнала для управления скоростью вентиляторов охлаждения на основе показаний температурных датчиков.

### 3. Управление питанием и памятью

*   **`bitmain_dc_dc.c`**
    *   **Роль:** Регулировка напряжения ядра (Vcore).
    *   **Логика:** Взаимодействует с ЦАП (DAC53401) для плавного изменения напряжения. Реализует алгоритмы пошагового повышения/понижения напряжения (ramp up/down) для поиска оптимальных точек эффективности.
*   **`bitmain_eeprom.c`**
    *   **Роль:** Чтение и запись энергонезависимой памяти.
    *   **Логика:** Управляет состоянием подключения к EEPROM хеш-платы. Сохраняет калибровочные данные, серийные номера и результаты предыдущих тестов.
*   **`eeprom_data_format_v4.c` / `eeprom_data_format_v5.c`**
    *   **Роль:** Парсер структур данных EEPROM.
    *   **Логика:** Декодирует бинарные данные из EEPROM, проверяет контрольные суммы (CRC5), обрабатывает версии форматов V4/V5. Извлекает информацию о модели чипа, версии PCB и заводских настройках.

### 4. Криптография и Безопасность

*   **`bitmain_security.c` / `xxtea.c`**
    *   **Роль:** Шифрование данных.
    *   **Логика:** Реализует алгоритм XXTEA для защиты обмена данными с PIC-контроллером и шифрования чувствительных полей в EEPROM. Гарантирует, что только авторизованная прошивка может изменять критические параметры.
*   **`hmac-sha256.c`**
    *   **Роль:** Хеширование.
    *   **Логика:** Используется для генерации подписей при общении с серверами MES (Manufacturing Execution System), обеспечивая целостность и аутентичность запросов.

### 5. Тестирование ASIC и Калибровка

Самая сложная часть системы, непосредственно взаимодействующая с чипами BM13xx.

*   **`driver-asic.c`**
    *   **Роль:** Низкоуровневый драйвер ASIC.
    *   **Логика:** Прямая запись в регистры чипов: настройка PLL (частота), сброс ядер, управление тактированием. Содержит таблицу битовых перестановок (`bit_swap_table`) для коррекции порядка байт при передаче данных.
*   **`bitmain_BM1368.c`**
    *   **Роль:** Специфичная логика для чипов BM1368.
    *   **Логика:** Проверка конфигурации, парсинг nonce (Software/AutoGen patterns), расчет хешрейта. Включает логику отправки данных на внешний сервер для анализа паттернов и сохранения найденных nonce.
*   **`pattern.c`**
    *   **Роль:** Генератор рабочих нагрузок.
    *   **Логика:** Управляет потоками отправки задач на ASIC и приема ответов. Рассчитывает статистику по ядрам и доменам напряжения. Инициализирует режимы тестирования (PT1/PT2).
*   **`sw_sweep.c` / `sweep.c`**
    *   **Роль:** Алгоритм частотного свипинга (Sweep Test).
    *   **Логика:** Пошаговое увеличение частоты ASIC для поиска максимального стабильного значения. Анализирует баланс нагрузки между доменами, выявляет "слабые" чипы и сохраняет оптимальные пары напряжение/частота в EEPROM. Поддерживает режимы `Over` (полный перезапуск) и `Online` (динамическая корректировка).

### 6. Сеть, Логирование и MES

*   **`bitmain_http.c`**
    *   **Роль:** HTTP/HTTPS клиент.
    *   **Логика:** Отправка результатов тестов на сервер MES, получение конфигурационных файлов и синхронизация времени. Использует HMAC-SHA256 для подписи запросов.
*   **`bitmain_MES_system.c`**
    *   **Роль:** Интеграция с производственной системой.
    *   **Логика:** Парсит JSON-ответы от сервера для получения стандартов тестирования, версий питания и профилей конфигурации. Управляет handshake-протоколом.
*   **`bitmain_log.c`**
    *   **Роль:** Подсистема логирования.
    *   **Логика:** Запись событий в файлы, ротация логов, сжатие (LZ4) и кодирование (Base64) для экономии места и безопасной передачи.
*   **`mk_time.c`**
    *   **Роль:** Синхронизация времени.
    *   **Логика:** Парсит заголовки HTTP Date и NTP-подобные ответы для установки системного времени, необходимого для корректных timestamp'ов в логах и токенах безопасности.

### 7. Периферия и Пользовательский интерфейс

*   **`fan.c`**
    *   **Роль:** Терморегуляция.
    *   **Логика:** PID-регулятор для управления скоростью вентиляторов. Предотвращает перегрев во время стресс-тестов.
*   **`7007_lcd.c`**
    *   **Роль:** Драйвер LCD дисплея.
    *   **Логика:** Вывод текстовой информации о статусе теста, ошибках и температуре.
*   **`bitmain_scan_code_gun.c`**
    *   **Роль:** Интерфейс сканера штрих-кодов.
    *   **Логика:** Считывание QR-кодов с хеш-плат для автоматического заполнения данных о модели, ревизии и серийном номере.

## 🛠 Технические детали реализации

*   **Язык:** C++11 (строгое соответствие стандартам, использование `static_cast`, `nullptr`, RAII где возможно).
*   **Архитектура:** ARM Cortex-A9 (Zynq PS) + FPGA Fabric (PL).
*   **Компилятор:** `arm-linux-gnueabihf-g++`.
*   **Ключевые библиотеки:**
    *   `pthread` для многопоточности (управление тестами, логирование, сеть).
    *   `jansson` для парсинга JSON (MES).
    *   `LZ4` для сжатия логов.
    *   `OpenSSL` (частично) для HMAC-SHA256.
*   **Протоколы:** I2C, UART, SPI, HTTP/JSON, XXTEA.
