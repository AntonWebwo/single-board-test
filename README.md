# Анализ программы первичной диагностики майнера Bitmain (Xilinx Zynq + BM13xx)

Данный репозиторий содержит подробный анализ и реконструкцию логики работы программного обеспечения для контрольных плат майнеров Bitmain (в частности, архитектур, схожих с Antminer S9/T9+), основанных на системе-на-кристалле **Xilinx Zynq** (ARM Cortex-A9 + FPGA Fabric).

Код получен в результате обратной разработки (reverse engineering) бинарных файлов прошивки. Основная цель — документирование низкоуровневого взаимодействия между центральным процессором, программируемой логикой (FPGA), ASIC-чипами на хеш-платах и периферийными устройствами.

## 📖 Архитектура системы

Система построена вокруг контроллера **Zynq 7000/7007**, который управляет:
1.  **ASIC-цепями:** Обмен данными через UART/SPI, реализуемый через логику FPGA для высокой скорости и параллелизма.
2.  **Управлением питанием:** Контроль DC-DC преобразователей и блоков питания APW через I2C/GPIO и ЦАП (DAC).
3.  **Терморегуляцией:** Чтение данных с датчиков температуры (ASIC, PCB, окружающая среда) и управление ШИМ (PWM) вентиляторами.
4.  **Безопасностью и идентификацией:** Работа с EEPROM, аутентификация через микроконтроллер PIC16F1704, защищенная загрузка.
5.  **Пользовательским интерфейсом:** LCD-дисплей и кнопки управления.
6.  **Сетью и логированием:** Взаимодействие с MES (Manufacturing Execution System), ротация логов, удаленный мониторинг.

## 📂 Структура проекта и описание скриптов

### Ядро платформы и инициализация

*   **`7007_common.c` / `platform.c`**
    *   **Назначение:** Центральная инициализация платформы и обнаружение возможностей.
    *   **Детали:** Обрабатывает последовательность запуска FPGA, GPIO и подсистем UART. Определяет подключенные хеш-платы, считывая регистры FPGA (`fpga_read(2, ...)`). Анализирует битовые маски для определения режима работы (например, режим "T9" или стандартный). Управляет глобальными состояниями, такими как `platform_inited`.

*   **`init.c` / `bitmain_main.c`**
    *   **Назначение:** Точка входа приложения и главный цикл управления.
    *   **Детали:** Настраивает обработчики сигналов (SIGTERM, SIGINT), инициализирует платформу и входит в основной цикл тестирования/майнинга. Оркестрирует поток между различными режимами тестирования (PT1, PT2, SWEEP, DropLevel) и обрабатывает пользовательский ввод через кнопку IP Report. Управляет жизненным циклом процесса майнинга, включая сканирование хеш-плат и проверку данных EEPROM.

*   **`bitmain_global.c`**
    *   **Назначение:** Управление глобальным состоянием и вспомогательные функции.
    *   **Детали:** Определяет глобальные структуры для истории результатов (`gHistory_Result`), контекста выполнения (`g_rt`) и конфигурации. Содержит вспомогательные функции для расчета статистики (скорость хеширования, средние частоты), управления состояниями потоков и обработки критических ошибок выхода.

### Уровень абстракции оборудования (HAL)

*   **`7007_fpga.c`**
    *   **Назначение:** Прямое взаимодействие с памятью, отображенной на регистры FPGA Xilinx Zynq.
    *   **Детали:** Реализует `mmap` для доступа к регистрам FPGA (`/dev/axi_fpga_dev`). Предоставляет функции `fpga_read` и `fpga_write`, использующие таблицы поиска (`t9_fpga_map`, `v9_fpga_map`) для трансляции логических адресов регистров в физические смещения памяти FPGA. Критически важно для низкозадержечной связи с ASIC.

*   **`7007_gpio.c`**
    *   **Назначение:** Управление линиями ввода-вывода общего назначения через sysfs.
    *   **Детали:** Экспортирует пины GPIO, устанавливает направление (IN/OUT) и считывает/записывает значения. Используется для управления линиями сброса, сигналами включения питания доменов и чтения состояния кнопок. Включает механизм обратных вызовов (callback) в отдельном потоке для асинхронных событий GPIO.

*   **`7007_i2c.c` / `7007_iic.c`**
    *   **Назначение:** Реализация шины I2C.
    *   **Детали:** Низкоуровневый драйвер для связи по I2C. Использует регистры FPGA для битбанга или контроля контроллера I2C. Обрабатывает блокировку мьютексов для безопасности потоков. Поддерживает как стандартные транзакции I2C, так и специфические чтения/записи регистров, требуемые PMIC (микросхемами управления питанием) и датчиками. `7007_iic.c` действует как обертка с логикой инициализации более высокого уровня.

*   **`7007_uart.c`**
    *   **Назначение:** Связь UART с цепями ASIC.
    *   **Детали:** Управляет FIFO буферами передачи и приема через регистры FPGA. Реализует точное время для отправки команд ASIC и получения данных nonce. Обрабатывает переключение скорости передачи (медленная для инициализации, быстрая для майнинга) и форматирование пакетов. Критично для расчета хешрейта и обнаружения ошибок.

*   **`7007_pwm.c`**
    *   **Назначение:** Управление широтно-импульсной модуляцией (PWM) для вентиляторов.
    *   **Детали:** Настраивает контроллеры PWM через регистры FPGA для регулировки скорости вентиляторов на основе показаний температуры. Поддерживает несколько каналов PWM для разных зон охлаждения.

*   **`7007_lcd.c`**
    *   **Назначение:** Драйвер LCD-дисплея.
    *   **Детали:** Записывает символьные данные в буфер дисплея через файловый дескриптор. Обрабатывает очистку экрана и обновление статусных сообщений (например, "Heating", "Testing", "Error").

### Драйверы периферийных устройств

*   **`bitmain_dc_dc.c`**
    *   **Назначение:** Управление DC-DC преобразователем и регулировкой напряжения.
    *   **Детали:** Взаимодействует с ЦАП (например, DAC53401) для установки напряжений ядра ASIC. Реализует алгоритмы плавного изменения напряжения (`set_dac_voltage_step_by_step`) для безопасного включения/выключения хеш-плат. Считывает телеметрию напряжения и тока.

*   **`fan.c`**
    *   **Назначение:** Управление тепловым режимом и PID-регулятор.
    *   **Детали:** Реализует PID-регулятор для поддержания оптимальных рабочих температур. Считывает данные с датчиков температуры и динамически регулирует рабочий цикл PWM. Включает логику фаз "охлаждения" и "нагрева" во время тестирования.

*   **`driver-asic.c` / `bitmain_BM1368.c`**
    *   **Назначение:** Специфичное управление цепью ASIC (BM1368/BM1398 и др.).
    *   **Детали:** Содержит низкоуровневые команды для сброса ядер ASIC, настройки PLL частоты, конфигурации масок тикетов и чтения статуса регистров. Реализует протокол отправки рабочих паттернов и приема nonce. Обрабатывает специфичные особенности инициализации ASIC.

*   **`bitmain_scan_code_gun.c`**
    *   **Назначение:** Интерфейс сканера QR-кодов/штрих-кодов.
    *   **Детали:** Парсит данные от USB/UART сканеров штрих-кодов, используемых на производстве. Извлекает серийные номера, идентификаторы партий и калибровочные данные из сканированных QR-кодов для заполнения структур EEPROM.

*   **`bitmain_security.c` / `xxtea.c`**
    *   **Назначение:** Шифрование данных и целостность.
    *   **Детали:** Реализует шифрование/дешифрование XXTEA для защиты связи с микроконтроллерами PIC и защиты данных EEPROM. Гарантирует, что только авторизованная прошивка может изменять критические параметры калибровки.

*   **`eeprom_data_format.c` / `eeprom_data_format_v4.c` / `eeprom_data_format_v5.c`**
    *   **Назначение:** Парсинг и валидация структуры данных EEPROM.
    *   **Детали:** Определяет двоичный макет данных, хранящихся в EEPROM хеш-платы. Включает проверки CRC5, версионирование (V4/V5) и поля для данных калибровки (напряжение, частота, смещения датчиков). Предоставляет функции для чтения, записи и валидации этих данных.

### Системные службы и сеть

*   **`bitmain_http.c`**
    *   **Назначение:** HTTP/HTTPS клиент для интеграции с MES.
    *   **Детали:** Общается с системой исполнения производства (MES) для отчетов о результатах тестов, загрузки файлов конфигурации и синхронизации времени. Реализует подписывание запросов HMAC-SHA256 для аутентификации.

*   **`bitmain_MES_system.c`**
    *   **Назначение:** Логика протокола высокого уровня для MES.
    *   **Детали:** Оркестрирует рукопожатие с сервером MES. Парсит JSON-ответы для получения стандартов тестирования, версий питания и профилей конфигурации. Управляет отправкой итоговых отчетов о тестах.

*   **`bitmain_log.c`**
    *   **Назначение:** Подсистема логирования.
    *   **Детали:** Ротирует файлы логов, сжимает их с помощью LZ4 и кодирует в Base64 для передачи. Поддерживает кольцевой буфер недавних событий для отладки.

*   **`ap_base64.c` / `base64_file.c` / `fileCompress.c`**
    *   **Назначение:** Утилиты кодирования данных и сжатия.
    *   **Детали:** Вспомогательные библиотеки для кодирования/декодирования Base64 и сжатия файлов LZ4, используемые преимущественно модулями логирования и загрузки MES.

*   **`mk_time.c`**
    *   **Назначение:** Синхронизация времени.
    *   **Детали:** Парсит заголовки дат HTTP и ответы, подобные NTP, для точной установки системных часов, что критично для временных меток логов и токенов безопасности.

### Логика тестирования и калибровки

*   **`pattern.c`**
    *   **Назначение:** Генерация тестовых паттернов и выполнение.
    *   **Детали:** Определяет рабочую нагрузку, отправляемую на ASIC во время тестирования (PT1/PT2). Управляет потоками для отправки работы, приема nonce и мониторинга температуры. Рассчитывает хешрейты и идентифицирует неисправные ядра.

*   **`sw_sweep.c` / `sweep.c`**
    *   **Назначение:** Частотный свипинг и оптимизация.
    *   **Детали:** Реализует режим теста "Sweep", который постепенно увеличивает частоту ASIC для поиска максимальной стабильной рабочей точки. Корректирует пары напряжения и частоты на основе ошибок в реальном времени и обратной связи по температуре.

*   **`bitmain_local_config.c`**
    *   **Назначение:** Парсинг локальной конфигурации.
    *   **Детали:** Читает `Config.ini` или аналогичные локальные файлы для переопределения параметров теста по умолчанию. Позволяет техникам устанавливать конкретные целевые значения напряжения/частоты без подключения к MES.
 
*   **`bitmain_BTC.c`**
    *   **Роль:** Основной исполнитель тестовых процедур.
    *   **Функционал:** Реализация конкретных тестов: `Single_Board_PT1_Test` (базовая проверка), `Single_Board_PT2_Test` (стресс-тест с паттернами), `Single_Board_Sweep_Test`. Управляет циклами нагрева/охлаждения и проверкой датчиков.

## 🛠 Технические детали

*   **Целевая архитектура:** ARM Cortex-A9 (Zynq PS) + FPGA Fabric (PL).
*   **Компилятор:** `arm-linux-gnueabihf-g++` со стандартом C++11.
*   **Ключевые протоколы:** I2C, UART, SPI, HTTP/JSON, XXTEA, HMAC-SHA256.
*   **Аппаратные компоненты:**
    *   **SoC:** Xilinx Zynq 7000/7007.
    *   **ASIC:** Bitmain BM1368, BM1398 и др.
    *   **MCU:** PIC16F1704 (для управления питанием и безопасности).
    *   **Датчики:** TMP451, NCT218, LM75A (датчики температуры I2C).
    *   **Питание:** DAC53401 (управление напряжением), блоки питания серии APW.
